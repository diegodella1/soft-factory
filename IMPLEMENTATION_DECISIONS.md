# Implementation Decisions — FactoryBot

## Open Questions Resolution (Section 10)

### 1. LLM Backend
**Decision**: OpenAI API (as specified by user)
- **GPT-4o** for complex tasks: ideation brainstorming, PRD generation, code generation, deployment planning
- **GPT-4o-mini** for lightweight tasks: intent detection, message routing, progress summaries
- Estimated cost: ~$50-80/month with one project at a time, well within $100 budget

### 2. Telegram Bot Framework
**Decision**: `python-telegram-bot` (Python)
- Python 3.11.2 is already on the Pi — no Docker needed for the bot itself
- Mature async library with excellent Telegram API coverage
- Lightweight memory footprint (~30MB)
- OpenAI Python SDK integrates cleanly

### 3. Agent Orchestration
**Decision**: State machine with an Orchestrator Agent
- Each project has a state: `ideation` → `prd_generation` → `prd_review` → `approved` → `development` → `deployment` → `deployed`
- Additional states: `paused`, `blocked`
- The Orchestrator reads `ORCHESTRATOR.md` (master workflow document) and routes messages to the correct agent based on project state
- Agents hand off by updating project state and writing outputs to the Project Memory Store
- No external task queue needed — single-project sequential workflow

### 4. Concurrent Projects
**Decision**: One at a time (as specified by user)
- Simplifies state management significantly
- Prevents RAM exhaustion on the Pi
- User can `/pause` current and `/resume` another

### 5. Budget/Cost Constraints
**Decision**: Up to $100/month (as specified by user)
- GPT-4o-mini used wherever possible to reduce costs
- GPT-4o reserved for code generation and complex reasoning
- Token limits enforced per agent call

## Additional Decisions

### 6. Project Storage Location
**Decision**: `/home/diego/Documents/soft-factory/projects/`
- Each project gets a slug-based subdirectory
- Contains: IDEA_SUMMARY.md, PRD.md, PROJECT_LOG.md, state.json, conversation_history.json, src/

### 7. Bot Deployment
**Decision**: Run as a systemd service (not Docker)
- The bot itself is lightweight — no need for containerization
- Projects it builds will use Docker/Coolify for deployment
- systemd ensures auto-restart on failure

### 8. Development Agent Strategy
**Decision**: Iterative code generation via OpenAI API
- Agent receives the PRD and creates a build plan (ordered list of tasks)
- For each task: generates code → writes to disk → executes commands → validates
- If errors occur: sends error context back to GPT-4o for debugging (max 3 retries per step)
- Uses subprocess for shell commands with timeout limits
- All generated projects go in the project's `src/` directory

### 9. Deployment Strategy
**Decision**: Docker + Coolify (as specified in PRD)
- Each project gets a Dockerfile generated by the Development Agent
- Deployment Agent creates docker-compose.yml if needed
- Registers app in Coolify via API
- Uses Coolify's built-in SSL/proxy (Traefik)
- Projects accessible at `http://192.168.1.14:<port>` (LAN) or via domain if configured

### 10. Conversation History
**Decision**: File-based per project
- `conversation_history.json` stores the last 50 messages per project
- Agents receive relevant conversation context (last 10-20 messages) plus the structured documents (IDEA_SUMMARY.md, PRD.md)
- Full history is not sent to LLM to manage token costs

### 11. Natural Language Intent Detection
**Decision**: GPT-4o-mini with a classification prompt
- Classifies user messages into: `new_idea`, `brainstorm`, `approve`, `question`, `scope_change`, `revisit`, `status_check`, `general`
- Falls back to current active agent if classification is ambiguous
- Commands (/new, /approve, etc.) bypass intent detection entirely

### 12. Error Handling in Development Agent
**Decision**: 3-retry loop with escalation
- Step fails → agent reads error, modifies approach, retries
- After 3 failures on same step → sends blocker message to user via Telegram
- User can provide guidance or skip the step
- All errors logged in PROJECT_LOG.md

### 13. Port Allocation for Projects
**Decision**: Auto-assign starting from port 3100
- Bot reads existing Coolify apps to find next available port
- Port stored in project's state.json
- Avoid conflicts with existing services (Supabase: 54321, Coolify: 8000)
